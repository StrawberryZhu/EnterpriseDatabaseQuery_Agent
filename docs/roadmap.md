# InsightForge Agent 开发路线图

## 版本原则

InsightForge Agent 从 `v0.1.0` 开始维护自己的版本。上游 QueryMind 的历史版本用于说明项目来源，不作为本项目的独立开发版本号。

路线图表示开发方向，不代表已完成能力。每项功能只有在代码、测试、文档和部署验证全部通过后才能标记完成。

## 已完成

### v0.1.0：安全基线与品牌迁移

- [x] 建立独立 GitHub 仓库和开发分支；
- [x] 确认 `.env`、本地配置和 API Key 不进入 Git；
- [x] 保存上游导入基线和运行截图；
- [x] 将页面、API、MCP、Docker 镜像和管理脚本统一为 InsightForge Agent；
- [x] 保留旧数据卷兼容，验证历史对话可继续访问；
- [x] 通过自动化测试和浏览器冒烟测试。

## 下一阶段

### v0.2.0：动态数据源接入

目标：允许用户在界面中配置并测试新的 PostgreSQL 只读数据源，而不是把 Northwind 固定写在代码中。

实施前设计见 [动态数据源数据模型设计](dynamic-data-source-design.md)。

- [x] 数据源模型、凭据隔离表和迁移框架；
- [x] 凭据认证加密、密钥版本和错误脱敏服务；
- [x] 数据源新增、编辑、连接测试、Schema 同步、启用和软删除接口；
- [x] PostgreSQL 只读连接测试与 Schema、表、字段、主外键和估算行数发现；
- [x] 数据源级只读策略、查询超时、Schema 白名单和 200 行限制；
- [x] 将活动数据源 Schema 接入 Context Builder，并隔离 Northwind 专属 RAG 知识；
- [x] 前端数据源列表、连接表单、测试、同步、启用和软删除操作；
- [x] 单元测试、集成测试和失败场景验证；
- [x] Northwind 注册为系统数据源并回填历史 Run；
- [x] Northwind 在动态查询链路中保持兼容。
- [x] 使用 Supabase Session Pooler、TLS、只读角色和 RLS 完成外部数据库验收；
- [x] 增加会话自动命名、重命名、置顶、取消置顶和删除；

## 暂不纳入当前范围

- 自动执行写入型 SQL；
- 直接连接未授权生产数据库；
- 在没有身份认证时开放公网访问；
- 保存模型推断出的敏感用户属性；
- 将 Docker Compose 宣称为高可用生产编排方案。

## 功能完成标准

每个路线图功能至少满足：

1. 需求边界和安全假设已记录；
2. 实现与现有架构一致；
3. 新增自动化测试，原有测试不回退；
4. Docker 环境可复现；
5. 浏览器关键路径无阻断错误；
6. README 或对应文档已更新；
7. 提交记录能清楚说明设计与验证结果。
